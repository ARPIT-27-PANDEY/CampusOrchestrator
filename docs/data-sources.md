# Data sources, provenance and maintenance

Every tool result carries a `source` block. Its fields mean exactly this:

| Field | Meaning |
|---|---|
| `mode` | `demo` = synthetic fixture, `imported` = snapshot of a real document/file, `live` = fetched from an upstream API at request time |
| `retrieved_at` | when **our service** produced this answer from its source (UTC) - the query time |
| `data_as_of` | the source's own update/issue date, **only** when the source states one; otherwise `null` |
| `imported_at` | when an operator-supplied file was read (cafeteria imports) |
| `stale` | `true` out of date, `false` current, `null` cannot be determined |
| `staleness_reason` | why it is stale or unverifiable |
| `record_version` | sha256 prefix of the file/fixture the answer came from |
| `source_url` | public page of the source (https only; filtered by the backend) |

`retrieved_at` and `data_as_of` are never used interchangeably: a lookup made seconds ago says nothing
about how current the underlying data is.

## Campus clock

All services decide "today" in `CAMPUS_TIMEZONE` (default `Asia/Kolkata`) at request time via an
injectable `CampusClock` (`campus_time.py`, identical in every package; a test keeps the copies in
sync). The host OS timezone is never used. The agent receives the campus date and tomorrow's date in its
system prompt and is told to pass explicit dates to tools; the UI shows the date the tool returned.

## Academics: official IIT Roorkee documents (`mode: imported`)

- Manifest: `services/academics_mcp/data/sources/iitr_sources.yaml` (hand-curated: official title, issuing
  authority, URL, listing page, issue date, Senate item, applicability, status, supersession).
- Fetch results: `iitr_sources.lock.json` (sha256, retrieval time, size, pages, extractable text, status).
- Files: `services/academics_mcp/data/iitr/<id>.pdf`.

17 documents from `iitr.ac.in/Academics` (Academic Calendar, Academic Regulations, General
Notifications): UG Ordinances 2025 (+ 2016, superseded), Ph.D. Regulations 2026 (+ 2019, superseded),
Autumn 2026-27 and Spring 2025-26 calendars, and Senate notifications on attendance, unfair means (2025
guidelines + 2026 revision), grading, second examinations, MTE re-examination, Academic Bank of Credits,
CGPA-to-percentage conversion, minor-programme CGPA, exit policy and grade moderation.

**Not indexed:** two scanned PDFs without a text layer (UG Ordinances 2016, Exit Policy 2022) are reported
as needing OCR in `source.not_indexed`; coverage is never claimed for them.

Applicability: passages carry `doc_status` (current/superseded), `applies_to` (e.g. `phd`,
`undergraduate`) and `superseded_by`. When a superseded document and its successor are both retrieved,
the current one ranks first and `applicability_notes` explains the relation; programme-specific
documents get a note so they are not presented as universal.

```bash
cd services/academics_mcp
python -m academics_mcp.sources fetch            # allowlisted hosts only; --dry-run, --only ID ...
python -m academics_mcp.sources check            # local files changed/missing vs the lock file
python -m academics_mcp.sources report           # status table
python -m academics_mcp.ingest --dry-run --json  # what would be added/replaced/removed/needs OCR
python -m academics_mcp.ingest --json            # (re)build the index; idempotent
```

To add a document: add an entry to the manifest (official title and date from the listing page), run
`sources fetch --only <id>`, then restart the server or run `ingest`. A failed download never replaces a
good file. For a document that cannot be downloaded, place the PDF at `data/iitr/<id>.pdf` manually and
record how it was obtained in the entry's `note`.

The fictional demo handbooks (`data/handbooks/`) remain for the v1 benchmark and tests only.

## Events (`demo` list, with `imported` official records)

`services/events_mcp/events_mcp/data/demo_events.json`, generated by
`services/events_mcp/scripts/build_events_fixture.py`:
- **83 official records** transcribed from the Autumn 2026-27 and Spring 2025-26 academic calendars
  (document + page on each record, absolute dates, all-day). Convocation 2026 is `tentative` with the
  calendar's wording ("19.09.2026 OR 26.09.2026"). Spring rows repeated in the Autumn calendar were taken
  once, from the newer document.
- **39 synthetic records** (`origin: synthetic`, organisers marked "(demo)") with dates relative to today,
  covering workshops, lectures, seminars, competitions, cultural, sports, careers, cancelled, rescheduled
  and completed events, all registration states, recurrence, multi-day and past-midnight events.

Optional live source: `EVENTS_PROVIDER=google` (public Google Calendar, API key; see
[google-calendar.md](google-calendar.md)). `retrieved_at` is the fetch time and `data_as_of` the API's
`updated` field (or `null`). A failing calendar is a tool error, never "no events".

## Library

**Campus catalogue (`mode: demo`)** - `services/library_mcp/library_mcp/data/demo_books.json`, built by
`services/library_mcp/scripts/import_catalogue.py` from a curated list of 144 titles: 138 matched Open
Library with confidence (title and author must agree) and carry Open Library's title, authors, first
publication year, publisher, ISBN-13s and work URL; 6 were skipped and are listed in
`scripts/import_catalogue_report.json`. Copies, availability, shelves, call numbers (`DEMO-…`) and due
dates are **synthetic** and say nothing about IIT Roorkee's library.

**Public book discovery (`mode: live`)** - tool `discover_public_books`, providers configurable with
`PUBLIC_BOOK_PROVIDERS` (default `openlibrary,openstax`; `googlebooks` optional with
`GOOGLE_BOOKS_API_KEY`). Access types:

| access_type | Meaning | Example |
|---|---|---|
| `open_access_download` | legal free full copy | OpenStax CC-licensed PDF; Google Books public-domain PDF |
| `open_access_read` | free to read in full online | Open Library "public" scan |
| `borrow_online` | controlled digital lending (account, one reader at a time) | Open Library "borrowable" |
| `preview_only` | partial preview | Google Books PARTIAL |
| `metadata_only` | record only | Open Library "printdisabled"/"no_ebook" |

Only provider-supplied links are returned (plus canonical record pages). Per-provider minimum interval
(1 s), one retry for transient errors, TTL cache (`PUBLIC_BOOK_CACHE_TTL_S`, 1 h), timeout
(`PUBLIC_BOOK_TIMEOUT_S`, 8 s) and partial results with a per-provider status.

Investigated but not integrated (from the development network, 2026-10-29): Google Books returned HTTP
429 without a key (adapter implemented, opt-in); DOAB's REST search returned HTTP 403 (no adapter);
gutendex.com (Project Gutenberg) failed TLS (public-domain titles are reachable through Open Library's
`public` scans instead).

## Cafeteria (`mode: demo` by default)

`services/cafeteria_mcp/cafeteria_mcp/data/demo_menu.json`, built by
`services/cafeteria_mcp/scripts/build_menu_fixture.py`: a **synthetic** four-week rotation (rotation
week from the campus date; anchor Monday 2026-10-05) for three demo locations (Central Cafeteria,
Hostel Mess, Night Canteen - all "(demo)"), 82 dishes, North/South/East/West Indian, regional,
Chinese, Italian and continental, breakfast/lunch/snacks/dinner/beverages. No allergen or nutrition data
is given. `mess.iitr.ac.in` failed TLS from the development network, so no official menu is used.

Imports: `CAFETERIA_PROVIDER=json|pdf` with `CAFETERIA_MENU_PATH` (rotation or single-week JSON; simple
PDF layout). Imported menus are `imported`, never `live`; outside their declared validity they are
`stale: true`, and without a validity window `stale: null` ("cannot be verified").

## Versioned fixtures

The v1 benchmark pins `demo_books_v1.json`, `demo_events_v1.json`, `demo_menu_v1.json` and the fictional
handbooks, so its results stay reproducible after the data expansion.
